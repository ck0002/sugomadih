# DnLLM — AI-Directed Terminal Dungeon Crawler

DnLLM is a terminal-based, ASCII-style dungeon crawler. The game combines a Python game engine with a React Ink terminal interface and an optional local language model that acts as a room director.

The player explores procedurally generated rooms, encounters characters, collects items, and moves deeper into the dungeon. When the local model is available, it selects room themes, layouts, features, enemies, NPCs, items, and short narration. The Python engine validates those choices and remains responsible for the actual game state and rules.

> **Project status:** the current implementation focuses on room generation and exploration. It is not yet a complete combat or save-based RPG. See [Known limitations](docs/known-limitations.md) for the features that are not implemented.

## Highlights

- **Terminal-first interface:** a first-person ASCII view, minimap, story panel, nearby-entity list, party panel, and inventory panel.
- **Procedural rooms:** several layouts, environmental features, themes, and a reachable exit are generated by the Python engine.
- **Optional local AI:** llama.cpp's `llama-server` serves a Qwen3.5 2B GGUF model; the model chooses from controlled content catalogues and produces room narration.
- **Safe fallback:** if the LLM server is unavailable or its response cannot be used, a schema-compatible random generator supplies a room plan.
- **Separated responsibilities:** Python owns game rules and state; the TypeScript UI renders state and sends player actions.
- **Testable without AI:** automated tests use the random LLM implementation and do not require model downloads or a running inference server.

## Technology

| Area | Technology |
|---|---|
| Game engine | Python 3.14+ |
| Python environment and commands | `uv` |
| Terminal UI | React 19, Ink 8, TypeScript, `tsx` |
| Local model server | llama.cpp `llama-server` |
| Model configured by the launcher | `unsloth/Qwen3.5-2B-GGUF:Q4_K_M` |
| Tests | pytest |

The Python project currently has no runtime third-party dependencies declared in `pyproject.toml`. `pytest` is listed as a development dependency. The UI has its own dependencies in `ui/package.json`.

## Requirements

- Python **3.14 or newer**.
- [`uv`](https://docs.astral.sh/uv/) available on `PATH`.
- Node.js and npm available on `PATH`.
- A terminal that supports Unicode characters and ANSI colours.
- **Optional, for AI-generated rooms:** a compatible llama.cpp build exposing `llama-server` on `PATH`. The provided launcher downloads the configured GGUF model on first use, so the first launch requires network access and enough disk space for the model and its cache.

The included LLM launcher is a Bash script. On Windows, use WSL or another Bash environment, or start a compatible `llama-server` separately. There is no dedicated native Windows launcher in the repository at present.

## Quick start

Clone the repository and enter its root directory:

```bash
git clone https://github.com/ck0002/sugomadih.git
cd sugomadih
```

Install the Python environment and development dependencies:

```bash
uv sync --dev
```

Install the terminal UI dependencies:

```bash
cd ui
npm install
cd ..
```

### Start with the local LLM

In **Terminal 1**, start the model server from the repository root:

```bash
./scripts/llm-server.sh
```

The script starts `llama-server` on port `8080` by default and configures the model declared in the script. The first run may download the model.

In **Terminal 2**, start the game:

```bash
cd ui
npm run dev
```

The UI starts the Python engine automatically. Keep the model server running while playing with AI-generated rooms.

### Start without the local LLM

The game can also be started without a running model server:

```bash
cd ui
npm run dev
```

The engine attempts to contact the configured local LLM endpoint. If it cannot reach the server, the room director falls back to `RandomLLM`. The UI displays `(LLM offline: random room)` for fallback-generated rooms. This mode is useful for trying the current exploration loop and running development checks without downloading a model.

## Tests and checks

Run the Python engine tests from the repository root:

```bash
uv run pytest -q
```

Run the TypeScript type check from the UI directory:

```bash
cd ui
npm run typecheck
```

The test suite covers map connectivity and exit placement, room-plan validation, offline fallback, room transitions, item pickup, and JSON-compatible game state. These commands are documented here; run them locally to verify your checkout.

## Configuration

| Variable | Used by | Default | Purpose |
|---|---|---|---|
| `LLM_PORT` | `scripts/llm-server.sh` | `8080` | Port used by `llama-server`. |
| `DNLLM_LLM_URL` | Python engine | `http://127.0.0.1:8080` | Base URL of the OpenAI-compatible llama-server API. The client appends `/v1/chat/completions`. |
| `DNLLM_SEED` | Python engine | unset | Optional random seed for reproducible engine and fallback randomness. |

If you change the model server port, set both sides consistently. For example, start the server with `LLM_PORT=8081 ./scripts/llm-server.sh`, then launch the UI with `DNLLM_LLM_URL=http://127.0.0.1:8081 npm run dev` from `ui/`.

More setup details and debugging tips are in [Installation](docs/installation.md) and [Troubleshooting](docs/troubleshooting.md).

## Contributing

When changing the project, keep the Python models and TypeScript mirrors in sync, preserve the JSON-lines protocol between `engine/server.py` and `ui/src/bridge/useEngine.ts`, and add or update tests for engine behaviour. See [Development](docs/development.md).

## Project identity

The GitHub repository is named `sugomadih`; the Python package and the internal project documentation use the name `dnllm` / `DnLLM`. The documentation uses **DnLLM** as the project title while retaining the repository URL for cloning.
